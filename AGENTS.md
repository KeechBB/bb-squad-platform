# Project working context

Read `docs/PROJECT_CONTEXT.md` before making changes. It is the English working
summary for this repository, maintained at the user's request.

Update that summary when work establishes new architecture facts, changes behavior,
commands, data flows, or operational constraints, or resolves an open question.
Keep it concise and current; replace obsolete facts and date material findings.
Distinguish verified code behavior from historical documentation and unverified
deployment state. Never put secrets, connection strings, or private user data in it.

For each task, inspect the relevant implementation as well: the summary is a map,
not a substitute for reading code. Record meaningful validation and its limits.
